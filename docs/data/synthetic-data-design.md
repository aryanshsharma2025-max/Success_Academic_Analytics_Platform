## 1. Purpose of the Synthetic Dataset

The purpose of this synthetic academic dataset is to provide a comprehensive, statistically varied, and referentially sound foundation for developing and testing the database schema, analytics algorithms, and basic prototypes of the Success & Academic Analytics Platform (SAAP).

### Key Objectives
1. **Compliance with Institutional Privacy (BR-011, Section 12):** Initial engineering stages must strictly utilize synthetic or anonymized data. Real student data cannot be processed without formal institutional authorization.
2. **Deterministic Reproducibility:** Dataset generation must be fully reproducible via pseudo-random seeding, allowing consistent unit, integration, and performance benchmarks.
3. **Multi-Cohort Simulation:** Generates multi-semester academic histories (transcripts, continuous assessments, attendance rosters, and backlogs) across diverse student academic archetypes.
4. **Referential Integrity Assurance:** Validates foreign keys, compound constraints, and numerical ranges before schema population, preventing orphan records.

## 3. Relationships and Structural Containment

The dataset establishes complete referential integrity across the academic hierarchy:

```
[ Departments (3) ]
       │
       ▼
[ Programs (3) ] ───► [ Semesters (24) ] ◄─── [ AcademicYears (4) ]
       │                      │
       ▼                      ▼
[ Batches (9) ]        [ Assessments (108) ] ◄─── [ Subjects (36) ]
       │                      │                          │
       ▼                      ▼                          ▼
[ StudentEnrollments ] ──► [ StudentMarks ]    [ AttendanceRecords ]
       ▲                      ▲                          ▲
       │                      │                          │
       └──────────────────────┴── [ Students (200) ] ────┘
                                         │
                        ┌────────────────┴────────────────┐
                        ▼                                 ▼
             [ SemesterResults (648) ]          [ BacklogRecords (52) ]
```

### Relational Constraints Enforced
1. **Programs $\rightarrow$ Departments:** Each program references an existing department (`CSE`, `ECE`, `MECH`).
2. **Batches $\rightarrow$ Programs:** Each batch belongs to an existing program and admission year (`2023`, `2024`, `2025`).
3. **Semesters $\rightarrow$ Programs & AcademicYears:** Semesters 1 to 8 mapped strictly to legitimate session terms.
4. **StudentEnrollments $\rightarrow$ Students, Programs, Batches:** Every student has exactly one program and cohort batch assignment.
5. **Assessments $\rightarrow$ Subjects & Semesters:** Assessments evaluate curriculum subjects within their proper semester terms.
6. **StudentMarks $\rightarrow$ Students & Assessments:** Student marks strictly bind to enrolled assessments with `marks_obtained <= max_marks`.
7. **AttendanceRecords $\rightarrow$ Students, Subjects, Semesters:** Attendance records link to subjects and semesters active during the student's enrollment.

## 4. Academic Variation & Student Archetypes

To prevent artificial homogeneity and support realistic analytics testing, students are categorized into six distinct academic archetypes/personas:

| Persona / Archetype | Distribution | Marks Range | Attendance Range | Backlog Probability | Academic Behavioral Pattern |
|---|:---:|:---:|:---:|:---:|---|
| **High Performer** | 15% | 85% – 95% | 88% – 98% | 0.0% | Consistently excels; high class test and exam scores; candidate for academic honors. |
| **Above Average** | 30% | 72% – 84% | 80% – 90% | $< 1.0\%$ | Stable performance; consistent attendance; strong subject mastery. |
| **Average** | 30% | 55% – 70% | 75% – 85% | $\approx 5.0\%$ | General cohort baseline; occasional low test scores; rare cleared backlogs. |
| **Improving** | 10% | 45% $\rightarrow$ 78% | 68% $\rightarrow$ 92% | Initial only | Starts weak in Semester 1 (struggling transition), shows progressive upward growth across terms. |
| **Declining** | 8% | 82% $\rightarrow$ 48% | 88% $\rightarrow$ 62% | Emergent | Starts strong in Sem 1/2, then exhibits sharp attendance decline and marks drop in recent semesters (triggers attention alerts). |
| **Struggling / At Risk** | 7% | 35% – 48% | 55% – 72% | High ($> 60\%$) | Chronic attendance deficit ($< 75\%$); multiple active and cleared backlogs; detention risk. |

## 5. Domain Integrity & Validation Rules

The generated dataset complies with the following domain validation rules:

1. **Marks Value Bounds (ERR-MRK-001):**
   $$0.00 \le \text{marks\_obtained} \le \text{max\_marks}$$
   - Class Test 1: $\text{max\_marks} = 20.00$
   - Mid-Semester Examination: $\text{max\_marks} = 30.00$
   - End-Semester Examination: $\text{max\_marks} = 50.00$
2. **Attendance Consistency (ERR-ATT-001):**
   $$0 \le \text{classes\_attended} \le \text{classes\_held}$$
   $$\text{attendance\_percentage} = \text{round}\left(\frac{\text{classes\_attended}}{\text{classes\_held}} \times 100, 2\right)$$
3. **Grade Point Average Limits:**
   $$0.00 \le \text{sgpa} \le 10.00 \quad \text{and} \quad 0.00 \le \text{cgpa} \le 10.00$$
4. **Subject Credit Constraints:**
   $$\text{credits} > 0.0 \quad (\text{Range: } 3.5 \text{ to } 6.0)$$
5. **Identifier Uniqueness:**
   - Primary Keys: 100% unique UUID v4.
   - Institutional Identifiers: Format `SYN-<AdmissionYear>-<Dept>-<Index>` (e.g., `SYN-2024-CSE-0042`).
   - Subject Codes: Unique curriculum codes (`CS101`, `EC201`, `ME301`).

## 6. Import Templates

To support controlled data ingestion testing (SCR-009 / SCR-010), four standard import templates are provided under `data/import_templates/`:

1. **`import_template_students.csv`:** Bulk student admission roster.
   - Header: `institutional_identifier,full_name,program_code,batch_name,admission_year,status`
2. **`import_template_marks.csv`:** Continuous internal assessment marks.
   - Header: `institutional_identifier,subject_code,semester_number,assessment_type,marks_obtained,max_marks`
3. **`import_template_attendance.csv`:** Subject-level attendance summaries.
   - Header: `institutional_identifier,subject_code,semester_number,classes_held,classes_attended`
4. **`import_template_results.csv`:** Terminal semester examination grades.
   - Header: `institutional_identifier,semester_number,sgpa,cgpa,result_status`

## 7. Dataset Regeneration & Execution Guide

### 7.1 Generator Command
The dataset can be deterministically re-generated with arbitrary student counts:

```bash
# Generate baseline 200-student dataset with default seed 42
python data/synthetic/generate_dataset.py --students 200 --seed 42

# Generate large-scale test dataset (e.g., 1000 students)
python data/synthetic/generate_dataset.py --students 1000 --seed 123
```

### 7.2 Validation Command
The validation suite performs multi-stage relational, range, and uniqueness checks:

```bash
python data/synthetic/validate_dataset.py
```

### Validation Suite Checklist
- [x] Check 1: File existence for all 13 CSV datasets.
- [x] Check 2: Exact column header and schema conformance.
- [x] Check 3: Primary key and unique key uniqueness verification.
- [x] Check 4: Foreign key referential integrity (zero orphan records).
- [x] Check 5: Assessment marks range bounds ($0 \le \text{marks} \le \text{max}$).
- [x] Check 6: Attendance counts validity ($\text{attended} \le \text{held}$).
- [x] Check 7: Attendance percentage mathematical precision.
- [x] Check 8: Domain uniqueness constraints (no duplicate marks or attendance rows).
- [x] Check 9: SGPA / CGPA bounds verification ($0.0 \le \text{GPA} \le 10.0$).

## 8. Privacy & Anonymity Statement

> [!IMPORTANT]
> **Zero Real Student PII Guarantee:**  
> All records in this dataset are programmatically generated using synthetic naming conventions (`Synthetic Student 001`, `SYN-2024-CSE-0001`), deterministic UUID namespaces, and statistical distributions. No personal names, real student registration numbers, phone numbers, email addresses, or proprietary institutional records are utilized. This dataset strictly complies with **SRS Business Rule `BR-011`** and **Section 25 (*Privacy and Security Requirements*)**.
